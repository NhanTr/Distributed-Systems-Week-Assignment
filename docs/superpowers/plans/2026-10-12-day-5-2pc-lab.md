# Day 5 Two-Phase Commit Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and document a runnable Python 2PC simulator with one coordinator, three socket-based participants, durable WALs, deterministic abort injection, and restart recovery.

**Architecture:** A focused `two_phase_commit.py` module will contain protocol constants, JSON-line RPC helpers, a durable WAL, participant/coordinator state machines, and reusable threaded TCP server wrappers. `run_demo.py` will compose four loopback servers for commit, abort, and recovery demonstrations; `unittest` will exercise units and the real socket topology.

**Tech Stack:** Python 3 standard library (`dataclasses`, `json`, `os`, `socket`, `socketserver`, `threading`, `unittest`)

**Spec:** `docs/superpowers/specs/2026-10-12-day-5-2pc-lab-design.md`

## Global Constraints

- Use only the Python standard library.
- Run one coordinator TCP server and three participant TCP servers on loopback addresses.
- Use newline-delimited JSON messages with `type`, `tx_id`, and optional metadata.
- Persist every protocol state transition before sending the message enabled by it; every WAL append must call `flush()` and `os.fsync()`.
- Any abort, timeout, unavailable participant, invalid reply, or malformed phase-1 response forces `GLOBAL_ABORT`.
- Runtime WALs belong under ignored `Day 5/wal/`; tests use temporary directories and operating-system-assigned ports.
- The simulator documents but does not solve 2PC blocking, Byzantine faults, partitions, or distributed deadlocks.

## Review Focus

- Duplicate vote requests and global decisions must be idempotent rather than creating contradictory state.
- A final truncated WAL line must be ignored, while corruption before the final line must raise `WALCorruptionError`.
- An unknown message type or missing/invalid transaction ID must return structured `ERROR` without crashing the server.
- An unavailable or non-responsive participant must force coordinator abort and remain visible in the returned vote/acknowledgement maps.
- Reusing a transaction ID after the coordinator has made a durable decision must return the recorded decision without starting a second 2PC round.
